# M1 实机验收清单

**范围**：M1（外部 OneBot 端点路径）的全链路手工验收。
**环境**：ZCode 桌面版 + 一个**正在运行且 QQ 已登录**的 NapCat。
**用法**：从上往下逐条勾选。任何一条不通过，先按 [§12 已知会失败的场景](#12-已知会失败的场景与期望的降级表现)
定位是环境问题还是插件缺陷。

- 被测插件：`napcat-zcode` v0.1.0
- 被测协议：OneBot 11（HTTP 或 WebSocket）
- 配套文档：[仓库根 README](../README.md)、[设计文档](superpowers/specs/2026-11-20-napcat-zcode-design.md)

> **关于「实测」的边界**：本清单是给**人工**在真实 NapCat 上跑的。
> 自动化部分（322 条 vitest）覆盖的是协议形状、配置读写、导出器与面板逻辑，
> **不覆盖**真实 NapCat 的 `message_seq` 边界语义 —— 那一项在 §5.12 单独列出。

## 3. 连接 NapCat

### 3.1 成功路径

- [ ] **3.1.1** 填入端点（例 `http://127.0.0.1:3000`）与 token → 点「连接」
- [ ] **3.1.2** 状态条变成 **`● 已连接 · <昵称> · 外部端点`**
      （`外部端点` 是 M1 唯一的连接模式标签）
- [ ] **3.1.3** 左栏出现会话列表，分「群」「好友」两段
- [ ] **3.1.4** 四个动作按钮与「导出▾」**此时仍置灰**，但置灰原因变了：
      从「尚未配置 OneBot 端点」变成 **「未打开会话」**；
      打开一个会话后变成 **「未选择消息」**；选中消息后才可点
      （按钮可点的条件是「宿主能力位齐 + 已打开会话 + 已选消息」，不是「连上了」就立刻可点）

### 3.2 失败态 A：连不上

- [ ] **3.2.1** 把端点改成不可达地址（例 `http://127.0.0.1:59999`）→ 点「连接」
- [ ] **3.2.2** 表单下方出现红色错误文案（连接类错误，不是「连接失败」的通用文案）
- [ ] **3.2.3** **合法但连不上的端点会被保存**（配置按用户意图落盘）——
      所以下次打开面板仍然是连接失败态；重新填回正确端点即可连上。
      这一步验证的是「能改回来」，不是「没写坏」
- [ ] **3.2.4** 端点形状非法时（`http://` 空主机、端口越界如 `:99999`、`htp://` 之类）
      → 报「端点不是合法的 URL…」/「端点缺少主机名…」/「端点端口越界…」/「unsupported endpoint scheme」
      之一，**且不写文件、不改内存态**
- [ ] **3.2.5** 验证 3.2.4 的「不写文件」：开 `${ZCODE_PLUGIN_DATA}/config.json`
      （未注入时 `~/.zcode/napcat-zcode/config.json`），`connection.endpoint` 仍是**上一个成功值**
- [ ] **3.2.6** 端点报错文案里**不出现 token 明文**（端点带 `?access_token=...` 或 `user:pass` 时尤其要确认）

### 3.3 失败态 B：token 错

- [ ] **3.3.1** 把 token 改成一个错的 → 点「连接」→ 报错
      （HTTP 端点的错误文案形如 `token 校验失败（HTTP 401 on get_login_info）：请检查 OneBot 的 access token`）
- [ ] **3.3.2** 错误文案里**不含**正确 token 的明文
- [ ] **3.3.3** 改回正确 token → 连上
- [ ] **3.3.4 token 留空 = 保留已保存的 token**：连上之后点「重新配置端点」→ **只改端点、token 留空**
      → 点「连接」→ 仍然连上（已存的 token 没被擦掉）；开 `${ZCODE_PLUGIN_DATA}/config.json`
      确认 `connection.token` 仍是原值
- [ ] **3.3.5 清除 token 只能显式做**：勾选 **「清除已保存的 token」** 且 token 留空 → 点「连接」
      → `connection.token` 变成空串（之后对带 token 的 NapCat 会连不上，属预期）

### 3.3b 非回环端点没设 token → 警告

- [ ] **3.3b.1** 端点填成非回环地址（例 `http://192.168.1.10:3000`）且**不填 token** → 点「连接」
      → 状态条上出现**黄色警告**（`⚠ 端点不在本机（…）且未设置 token：…`），表单上也有一条同样的警告
- [ ] **3.3b.2** 端点是回环（`127.0.0.1` / `localhost` / `::1`）且不填 token → **没有**警告
- [ ] **3.3b.3** 端点非回环但**填了** token → **没有**警告
- [ ] **3.3b.4** 警告**不是**错误：连接失败与否仍由状态条的主文案决定

### 3.4 失败态 C：需扫码（NapCat 在线但 QQ 未登录）

- [ ] **3.4.1** 在 NapCat 里退出 QQ 登录 → **重新打开面板或新开会话**
      （面板挂载时会重新拉一次连接状态）
- [ ] **3.4.2** 状态条变成 **`✕ <错误文案>`**（错误来自 NapCat 本身）
- [ ] **3.4.3** **M1 没有专门的「需扫码登录」状态** —— 这是已知限制
      （README「已知限制与路线图 → 实测得出的坑」第 11 条），
      M1 只区分「未配置 / 连接失败 / 已连接」三态
- [ ] **3.4.4** 重新扫码登录 → 点「重试」→ 恢复 `● 已连接 · <昵称> · 外部端点`

### 3.5 断连与恢复

- [ ] **3.5.1** 停掉 NapCat → **重新打开面板或新开会话** → 状态条变 `✕ ...`，页面出现
      **「重试」** 与 **「重新配置端点」** 两个按钮
      （这两个按钮只在连接失败态出现；已连接态下 NapCat 挂掉，状态条要等下一次状态刷新才变）
- [ ] **3.5.2** 点「重新配置端点」→ 出现配置表单（端点**不预填**，避免无声覆盖已有配置）
- [ ] **3.5.3** 重启 NapCat → 点「重试」→ 恢复已连接
- [ ] **3.5.4 M1 没有自动重连**：把 NapCat 停掉后**什么都不点**、干等 1 分钟 →
      状态条**不会自己变回已连接**（没有指数退避重连循环，也没有进度提示）。
      WebSocket 只在**下一次调用**时懒建连，所以恢复要靠手动点「重试」或重新打开面板

## 5. 消息流

- [ ] **5.1** 首次打开会话，右栏出现**最近 100 条**消息，时间正序（早 → 晚）
- [ ] **5.2** 每条显示 `HH:mm 发送人 正文`（面板是三段并排显示；
      `[HH:mm] 发言人：内容` 是**注入体 / 导出文档**的格式，不是面板的渲染格式）；
      有引用时上方多一行 `↪ 引用预览`
- [ ] **5.3** 图片消息正文显示为 `[图片]`（**M1 不下载图片**，只渲染占位符）
- [ ] **5.4** 语音 / 视频 / 文件 / 合并转发分别渲染成 `[语音]` / `[视频]` / `[文件 name]` / `[合并转发]`
      （合并转发**不展开**子消息 —— M1.1 才做）
- [ ] **5.5** **向上滚动到顶部** → 自动加载更早的一页，插入后**视口不跳**
      （仍停在刚看的那条附近）
- [ ] **5.6** 顶部**常驻**一个「加载更早」按钮（只要还能翻就会显示，不依赖 `IntersectionObserver`）——
      不想靠滚动、或环境里没有 `IntersectionObserver` 时可以直接点它
- [ ] **5.7** 反复向上滚能持续加载更早的消息；**边界那条不会重复出现**
      （面板按 `seq` 跨调用去重）
- [ ] **5.8** 翻到底时顶部给出中文原因，四选一：
      - `没有更早的消息了（服务端返回空页）`
      - `服务端未提供可继续向前翻页的游标（消息缺少 message_seq）`
      - `本轮没有返回新消息（边界重复或已到历史开头）`
      - `游标没有前进（服务端未接受该游标），无法加载更早的消息`
- [ ] **5.9** 底部提示**不会**出现「没有更多了」这类含糊文案
- [ ] **5.10 渲染上限**：在一个消息数超过 2000 的会话里，顶部出现提示条
      **`仅显示最近 2000 条，导出/搜索可处理更多`**，且只渲染最近 2000 条
- [ ] **5.11 切换会话**：从会话 A 切到 B → 消息清空并重拉 B；A 的选择被清空；
      底部的 `已选 N 条` 归零
- [ ] **5.12 `message_seq` 边界语义（自动化覆盖不了，必须实机确认）** —— 记下 NapCat 版本号，
      并确认下面几件事（**两条路径的约定不一样，别混**）：

  **A. 面板翻页路径（`napcat_get_history`）**
  - 向上翻页时**边界那条会不会重复返回**（插件按「独占」语义下发游标，面板再按 `seq` 跨调用去重；
    若 NapCat 实际是「包含」语义，去重后用户侧看不到重复，但原始工具返回里会有重复）
  - 翻到历史开头时 `napcat_get_history` 的 `nextBeforeSeq` 是不是仍非空
  - `count` 会不会被服务端钳制（实际返回条数 < 请求的 `count`）

  **B. 导出现拉路径（`napcat_export` → `fetchMessagesBetween`）—— 游标约定不同**
  - 这条路径下发的是 **`message_seq = cursor + 1`**（`actions.ts` 的 `fetchMessagesBetween`）。
    按插件假定的「**独占**」语义（服务端返回 seq < message_seq），这等于请求
    「seq ≤ cursor」的一页，**边界含在内**；随后按 `fromSeq ≤ seq ≤ toSeq` 过滤，
    区间两端**都是闭区间**
  - 实测确认：用 `fromSeq` / `toSeq` 精确取一条已知消息 → 导出结果里**该条在**（闭区间成立）
  - 实测确认：把 `toSeq` 设成某条消息的 seq → 该条**在**导出里（不是被排除）
  - **若 NapCat 实际是「包含」语义**（服务端返回 seq ≤ message_seq）：这条路径会多取到
    `cursor + 1` 那一条，但区间过滤会把它剔掉 → **导出的区间内容仍然正确**；
    真正的风险是**触底附近**：「游标没有前进」的探测可能误判，
    导致导出**响亮失败**（`history pagination made no progress at cursor N; …`）而不是干净地完成。
    → 实测确认：导出一个**一直拉到历史开头**的区间，要么成功、要么响亮报错，
    **不能静默少一条边界消息**
  - 两处口径差异的根源：面板路径下发 `message_seq = cursor`（独占语义下不含边界），
    导出现拉路径下发 `message_seq = cursor + 1`（独占语义下含边界）——
    **不要用其中一条的观察去推断另一条**

  **C. 语音时长字段名**
  - 找一条**语音**消息，看 `napcat_get_history` 返回的 `segments` 里 `kind:"voice"` 的
    `duration` 是不是合理值（不是 `NaN`、不是巨大数值）
  - 插件依次尝试 `seconds` / `duration` / `time` 三个字段名（`model/message.ts` 的 `normalizeSegment`），
    **真实 NapCat 用的是哪一个待实测**
  - 若三个候选字段名**都取不到**：`duration` 键在序列化结果里**直接不存在**
    （`JSON.stringify` 会丢掉值为 `undefined` 的键，不会变成字符串 `"undefined"`），
    且面板**从不展示时长** —— 只渲染 `[语音]` 占位符（`duration` 在 `src/panel/` 里根本没被引用）

  → 结论记到 §13；这些是 M1 收尾计划里明确要实测确认的语义点。

## 7. 选择（四种方式）

- [ ] **7.1 单击** —— 点一条 → 只有它被选中，底部显示 `已选 1 条`
- [ ] **7.2 单击另一条** → 选区被**替换**成这一条（不是叠加）
- [ ] **7.3 Shift + 点击** —— 普通单击第 1 条（这成为**锚点**），再 Shift 点第 5 条 → 1–5 都被选中
- [ ] **7.4 锚点只由「普通单击」更新** —— Ctrl 点选与 Shift 点选都**不会**改变锚点
- [ ] **7.5 Shift 是并集语义** —— 普通单击第 10 条（选区 = {10}）→ Shift 点第 12 条
      （选区 = {10,11,12}）→ Ctrl 点第 3 条（选区 = {10,11,12,3}）→ Shift 点第 5 条
      → 锚点仍是第 10 条 → 区间 5–10 被**并入** → 选区 = {3,5,6,7,8,9,10,11,12}，
      **第 3 条没有被替换掉**
- [ ] **7.6 Ctrl / Cmd + 点击** —— 点一条 → 切换它在 / 不在选区里，其余不动
- [ ] **7.7 拖拽划选** —— 按住一条消息不动、拖过中间几条后松开 → 中间区间被选中
- [ ] **7.8 拖拽后不误触发单选** —— 拖拽结束后，浏览器补的那个 click 不会把区间改成单选
- [ ] **7.9 Ctrl + 拖拽** —— 与已有选区**合并**
- [ ] **7.10 底部统计** —— `已选 N 条` 与时间跨度 `HH:mm–HH:mm` 随选区实时更新
      （跨度按选区里最早 / 最晚的消息时间算）
- [ ] **7.11 切换会话后选区清空**

## 11. agent 侧直接调用 8 个工具（冒烟）

在 ZCode 的对话里直接让 agent 调这 8 个工具，或用 MCP 客户端直连
（`command: node`，`args: ["<插件目录>/dist/server.mjs"]`）。

- [ ] **11.1 `napcat_status`** —— 无入参 → 返回
      `{configured, connected, mode, login}`；`mode` 为 `external`；
      **连接失败时 `isError` 仍是 `false`**（那是状态，不是工具错误）
- [ ] **11.2 `napcat_list_chats`** —— `{kind:"group"}` → `{chats:[{kind,id,name,memberCount?}]}`；
      `{kind:"friend"}` 同理；`id` 是字符串
- [ ] **11.3 `napcat_get_history`** —— `{chatKind:"group", chatId:"<群号>", count:100}` →
      `{messages, nextBeforeSeq, exhausted}`，时间正序；
      `chatId` **传数字**也要能用
- [ ] **11.4 `napcat_get_history` 翻页** —— 把上一步的 `nextBeforeSeq` 作为 `beforeSeq` 再调 →
      拿到更早的一段；窗口不满时 `exhausted` 为 `true`
- [ ] **11.5 `napcat_search_messages`** —— `{chatKind:"group", chatId:"<群号>", query:"<正文中出现过的词>"}` →
      `{hits:[{message,contextBefore}], scanned, pages, exhausted, hitsTruncated, note}`；
      `note` 里明确说明这是**有限扫描**
- [ ] **11.6 `napcat_format_selection`** —— `{messages: <上一步 messages>, chatName:"测试群"}` →
      `{text, count, truncated}`；`text` 首行是 §10 的声明；`count` 是实际渲染的条数
- [ ] **11.7 `napcat_export`** —— `{chat:{kind:"group",id:"<群号>",name:"测试群"},
      messages: <消息数组>}` → `{mdPath, jsonPath, gitignoreUpdated}`；
      两个路径真实存在，`gitignoreUpdated` 是布尔
- [ ] **11.8 `napcat_export` 现拉模式** —— 不传 `messages`，改传
      `{chat, chatKind:"group", chatId:"<群号>", fromSeq:<小 seq>, toSeq:<大 seq>}` → 导出该区间；
      `fromSeq > toSeq` → 报错；`chat` 与 `chatKind/chatId` 不一致 → 报错
- [ ] **11.8.1 现拉模式的区间是闭区间** —— 用**一条已知消息的 seq** 同时当 `fromSeq` 与 `toSeq`
      → 导出的 `.json` 里**有且只有这一条**（区间两端都含）
- [ ] **11.8.2 现拉模式是「响亮失败」** —— 把 `toSeq` 设成一个 NapCat 不认的 seq，
      或让区间跨到没有 `message_seq` 的页 → 返回 `isError: true` + `{error}`，
      错误文案形如 `history pagination made no progress at cursor N; the server ignored message_seq` /
      `history pagination exceeded page limit (1000)`；
      **不会**静默写出一份「看着像成功、其实是残缺区间」的导出
      （对比：`napcat_get_history` 取不满是**正常返回**，靠 `exhausted` 表达，不是错误）
- [ ] **11.8.3 拉到历史开头的区间** —— 用一个很小的 `fromSeq`（早于该会话最早的消息）导出 →
      要么成功导出一份完整区间，要么**响亮报错**；
      **不能**静默少掉第一条（这条是 §5.12-B 的实测落点）
- [ ] **11.9 `napcat_get_config`** —— 无入参 → 返回当前配置；
      **token 设了时显示为 `***`、未设置时是空串**，
      端点是脱敏形态（去掉 query 与 userinfo）
- [ ] **11.10 `napcat_configure`** —— `{endpoint:"http://127.0.0.1:3000", token:"<token>"}` →
      `{configured:true, connected:true, login}`；
      **注意这一步会覆盖已有配置**，验收后确认端点仍然正确
- [ ] **11.11 `napcat_configure` 不带 token** —— `{endpoint:"http://127.0.0.1:3000"}`（不带 `token`）→
      **已保存的 token 保留不变**（开 `config.json` 确认 `connection.token` 还是原值）；
      要清除必须显式 `{endpoint, clearToken:true}`

## 12. 已知会失败的场景与期望的降级表现

这些是**设计如此**或**上游限制**，不是缺陷。验收时确认表现与本表一致即可。

| # | 场景 | 期望表现 |
|---|------|----------|
| 12.1 | 宿主不支持 `ui/message` / `ui/update-model-context` / `ui/download-file` | 对应按钮**置灰**并给出 `宿主不支持 <方法>（缺少能力位 <cap>）`；导出不受影响 |
| 12.2 | 宿主丢弃 `ui/download-file` 的保存路径 | 「另存一份…」**拿不到路径**，也**分不清取消与失败**；提示保持中性，不谎称「已保存到 X」 |
| 12.3 | 平台没有 composer 附件 API | 「添加到输入框附件区」只能走「保存为附件… → 复制 `@路径` → 粘贴」三段式 |
| 12.4 | OneBot 11 没有服务端搜索 | 搜索只能**向更早翻页后本地过滤**；返回里带 `scanned` / `pages` / `hitsTruncated` / `note` 说明扫描有限 |
| 12.5 | `exhausted` 的三合一语义 | 它**不等于**「没有更多了」；判断还有没有更早消息以「再翻一页是否返回空」为准 |
| 12.6 | 「包含图片」勾选 | **M1 不下载任何媒体**；导出里图片只是占位符 + URL；面板上的开关是禁用的 |
| 12.7 | 合并转发消息 | 只渲染 `[合并转发]` 占位符，不展开子消息（M1.1） |
| 12.8 | 消息数超过 2000 | 只渲染最近 2000 条，顶部提示 `仅显示最近 2000 条，导出/搜索可处理更多` |
| 12.9 | NapCat 在线但 QQ 未登录 | **M1 没有「需扫码」专态**，表现为连接失败（`✕ <错误>`），错误文案来自 NapCat |
| 12.10 | Shift 连选 | **并集语义**（叠加），不是替换区间 |
| 12.11 | 工作区导出但工作区目录不可用 | 「保存为附件…」如实报错 + 给「改用用户目录」退路；**不静默改写目的地**。<br>「导出▾ → 导出到当前工作区」只有报错、没有退路（那里目的地是用户显式选的） |
| 12.12 | `.gitignore` 已有覆盖规则 / 取反规则 | 不改文件；`gitignoreUpdated: false`（**两种含义**，插件不替用户断言是哪一种） |
| 12.13 | 配置里 `export.dir` 与设置界面冲突 | **env 合法值优先**（env 覆盖 `config.json`）；清单两项 `userConfig` 默认是空串，
      用户没显式选过时文件保持权威 |
| 12.14 | 本机没有可自动探测的 NapCat | M1 **不做**自动探测；必须手填端点（M2） |
| 12.15 | NapCat 上游已归档 | 官方 `NapNeko/NapCatQQ` 主分支只剩 README、npm `napcat` 包已注销；
      可用发行物在镜像仓库 `XingYunStar/NapCatQQ` 的 release（v4.18.42）。
      **本插件不下载 NapCat**（M2/M3 才做） |
| 12.16 | NapCat 挂掉 / 网络中断 | **M1 没有自动重连**（无指数退避循环、无进度提示）：状态条停在 `✕ ...`，
      恢复靠手动点「重试」或重新打开面板 |
| 12.17 | 工作区导出失败后改了选区再点「改用用户目录」 | 导出的是**失败那一刻**的旧选区（退路按钮捕获了当时的选区快照）；
      要导出新选区请重新点一次「保存为附件…」 |
| 12.18 | 端点不是回环且没设 token | **插件会警告**（是警告，不是错误）：状态条与表单上出现
      `⚠ 端点不在本机（…）且未设置 token：同网段的其他人可能读到你的 QQ 聊天记录…`；
      回环端点（`127.0.0.0/8` / `::1` / `localhost`）或已设 token 时**不**警告 |
